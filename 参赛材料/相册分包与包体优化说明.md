# 红韵乔林相册分包与包体优化说明

## 一、优化原因

小程序已经收录16张可展示的实拍与史料图片，后续还会继续增加旧址全景、铭牌、人物、文物、便民设施和研学活动照片。若全部图片长期放在主包，地图首页、定位和路线等核心功能会与相册素材共同占用主包空间，既影响首次下载，也会很快触及包体限制。

## 二、实施方案

项目将实景相册页面和全部本地实拍/史料图片放入同一个微信分包：

```text
主包
├─ 首页地图
├─ 村落与旧址详情
├─ 路线推荐、研学打卡、知识闯关
├─ 纠错、后台、可信与隐私
└─ 公共数据与业务工具

assets 分包
├─ gallery/index（实景相册页）
└─ images/（实拍与史料图片）
```

用户首次打开首页时无需下载大批相册图片；只有进入“实景相册”时才加载 `assets` 分包。相册页面仍通过统一内容服务读取云端已发布数据，云端不可用时回退本地已审核条目。

## 三、当前自动测量结果

运行：

```powershell
node scripts/release-readiness.js
```

当前静态预估结果：

- 主包：约0.25 MB；
- `assets`相册分包：约1.63 MB；
- 小程序总体：约1.88 MB；
- 12个页面全部完成四件套注册检查，其中1个为分包页面。

该结果是仓库静态文件预估，不包含微信开发者工具最终压缩、编译产物和平台处理。正式发布证据应补充开发者工具“代码质量/包体分析”截图。

## 四、验证范围

自动回归检查以下内容：

1. `app.json`中主包与分包页面均存在完整的 JS、JSON、WXML、WXSS 文件；
2. 旧址详情、村落详情和相册分享路径均指向新的分包路由；
3. 相册仍调用 `getPhotoGallery` 获取已发布内容；
4. 所有标记为可展示的本地图片路径真实存在；
5. 主包、单个分包和总体积分别计算，超出目标时体检失败。

## 五、后续素材策略

- 每张原图保留归档版，进入小程序前输出适合手机浏览的压缩副本；
- 普通展示图建议控制在100–250 KB，文字证件图优先保证可读性；
- 大批新增图片优先使用云存储缩略图与按需原图，不无限增加本地分包；
- 核心离线素材保留本地，非核心扩展相册采用云端加载和缓存；
- 每次新增素材后必须重新运行发布体检并在开发者工具复核包体。
