# 红韵乔林管理后台部署与权限说明

## 1. 功能定位

管理后台用于支撑实践团队离开后的长期内容维护，形成“村级录入—团队校对—文旅审核—正式发布”的闭环。游客可以看到管理入口，但所有写入、审核和发布操作都由云函数根据微信 OPENID 再次鉴权，前端页面不承担安全判断。

## 2. 部署顺序

1. 在微信开发者工具中开通云开发，创建云环境。
2. 将云环境 ID 填入 `miniprogram/app.js` 的 `globalData.env`。
3. 上传并部署 `contentService`、`visitorRecords`、`contentAdmin` 三个云函数，选择“云端安装依赖”。
4. 创建集合：`villages`、`places`、`stories`、`media`、`routes`、`checkins`、`corrections`、`adminRoles`。
5. 先把内容集合权限设置为“所有用户不可直接写”，所有写入统一经云函数完成。
6. 在 `adminRoles` 集合中配置管理员角色，随后从“村情信息—资料录入与审核”进入管理页验证。

## 3. adminRoles 数据示例

每名管理员一条记录，`_openid` 必须使用该管理员真实微信 OPENID。

```json
{
  "_openid": "管理员OPENID",
  "role": "recorder",
  "displayName": "乔林村资料录入员",
  "enabled": true
}
```

可用角色：

- `recorder`：新建、修改本人草稿并提交审核。
- `teamAdmin`：具备录入能力，可承担实践团队资料整理工作。
- `reviewer`：查看待审核队列，通过后正式发布或驳回补充。

比赛演示建议准备三个不同微信账号，分别展示提交、审核和游客只读效果。如现场只能使用一个账号，可将该账号配置为 `reviewer`，先演示保存与提交，再演示审核发布。

## 4. 内容状态

内容状态依次为：

`draft` 草稿 → `pending` 待审核 → `published` 已发布

驳回后状态为 `rejected`，录入员补充来源、说明等信息后可再次提交。游客端 `contentService` 只查询 `published` 内容，避免未经核验的史料直接展示。

## 5. 安全与合规

- 管理角色以云端 OPENID 为准，不信任前端传入的用户身份。
- 集合名称采用白名单，禁止任意集合读写。
- 发布、审核等敏感字段由云函数控制，录入员不能直接伪造。
- 历史人物、革命文物和证明材料必须填写来源；涉及个人照片须取得授权。
- GitHub 仓库不提交云环境私密配置、上传密钥或个人联系方式。
- 正式上线前应在微信公众平台补充隐私保护指引和位置权限用途说明。

## 6. 验收清单

- 未配置云环境时，游客图集仍能读取本地素材。
- 无管理员角色的用户无法保存或审核资料。
- 录入员可以保存草稿和提交审核，但不能发布。
- 审核员可以读取待审核队列、通过或驳回。
- 已发布图片能够出现在图集页，未发布图片不可见。
- 弱网打卡进入本地队列，恢复网络后自动补传且不产生重复记录。
