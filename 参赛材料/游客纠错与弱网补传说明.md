# 游客纠错与弱网补传说明

## 功能价值

红色史料、人物身份和地图位置都需要持续核验。小程序在旧址详情页提供“我要纠错”入口，游客可针对当前位置、史实内容、图片归属和文字错漏提交线索，解决实践团队离开后无法及时发现问题的维护难题。

## 使用流程

旧址详情 → 我要纠错 → 选择错误类型 → 填写依据 → 提交 → 管理端审核后修改资料。

当前版本不要求游客填写姓名和手机号。页面提示用户不要提交无关个人隐私，公开内容不会因单次纠错直接改变，必须经过管理员核验。

## 弱网设计

- 云环境未配置、网络异常或云函数暂时失败时，文字纠错先保存在本机队列。
- 下次进入纠错页且网络恢复时，系统自动补传。
- 队列最多保留最近 50 条记录，防止无限占用本地空间。
- 云函数从微信上下文获取 OPENID，前端不能伪造提交人身份。

## 后台数据

纠错记录写入 `corrections` 集合，主要字段包括：

- `_openid`：提交人的微信云端身份。
- `targetType`、`targetId`：被纠错资料的类型和编号。
- `errorType`：地图位置、史实、图片归属、文字错漏或其他。
- `description`：纠错说明，最长 1000 字。
- `status`：初始为 `pending`。
- `submittedAt`：云端提交时间。

## 测试结果

`tests/correctionService.test.js` 已验证离线入队、恢复网络补传、云端提交参数和队列清空逻辑。全量静态回归在加入纠错页后共检查 122 个源码文件，全部通过。
