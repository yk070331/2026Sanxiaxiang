# 红韵乔林需求分析与功能设计

## 1. 项目背景

乔林村及井冈山周边拥有红色旧址、历史人物资料、生态资源和研学价值，但资料分散、点位难寻找、现场讲解依赖人工、研学过程难记录，村级资料也缺少持续维护机制。“红韵乔林”以微信小程序为载体，为游客、研学团队和村级管理者提供可导航、可讲解、可互动、可维护的数字服务。

## 2. 目标用户与需求

### 游客

- 快速找到乔林村、乔林水库和革命旧址。
- 了解距离、路线、开放信息和安全提示。
- 浏览真实照片、红色故事与文物史实。
- 在弱网环境下继续查看核心内容。

### 学生与教师

- 按30分钟、60分钟或半日时长选择研学路线。
- 扫码进入点位讲解并记录打卡。
- 完成知识任务并形成研学成果。
- 查看资料来源，避免未经核验的历史内容。

### 村级录入员与审核人员

- 持续增加村落、旧址、故事、图片和路线。
- 对姓名、时间、地点和坐标进行分级审核。
- 接收游客纠错并保留处理记录。
- 无需修改前端代码即可更新正式内容。

## 3. 功能架构

### 地图导览

- 全域地图、点位搜索、类别筛选、当前位置。
- 腾讯地图核验坐标与一键导航。
- 距离估算、路线推荐和下一站提示。

### 内容展示

- 村落概况、革命旧址、红色故事、实景相册。
- 文物史实独立分类，记录来源和核验状态。
- 普通话讲解、字幕和关怀模式。

### 研学互动

- 30分钟初心线、60分钟研学线、半日乡村线。
- 点位二维码、现场打卡、电子纪念章。
- 知识问答、研学任务和结业证书。

### 数据管理

- 云端已审核数据读取与本地数据降级。
- 游客打卡同步和资料纠错。
- 村级录入员、团队管理员、审核员三级权限。
- 草稿、待审核、已发布、已驳回的内容流程。

## 4. 核心业务流程

### 游客研学流程

进入首页 → 定位或搜索乔林村 → 选择研学路线 → 导航至点位 → 扫码查看讲解 → 完成打卡与答题 → 获得纪念章 → 完成路线并生成证书。

### 资料发布流程

录入员保存草稿 → 提交审核 → 团队管理员整理 → 审核员核对史料与授权 → 正式发布 → 小程序云端读取 → 游客发现问题后提交纠错。

## 5. 非功能需求

- 稳定性：云端异常时核心内容自动使用本地数据。
- 性能：首屏避免等待远程请求，图片使用压缩副本和懒加载。
- 安全：云函数限制集合和操作，前端不保存密码或密钥。
- 隐私：定位只用于即时服务，不默认上传或长期保存。
- 可访问性：关怀模式放大字体和按钮，音频提供文字内容。
- 可维护性：数据、服务和页面分层，关键操作保留日志。

## 6. 版本规划

- V1.0：地图、村落详情、路线推荐、相册、文物史实、本地打卡。
- V1.1：云数据库、云函数、云端打卡、纠错和审核流程。
- V1.2：语音讲解、知识任务、电子证书、管理页面。
- V2.0：多村复制、学校研学管理和数据统计。
